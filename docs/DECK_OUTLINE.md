# Vinyas — Pitch Deck Outline (`docs/DECK_OUTLINE.md`)

Every number in this deck traces strictly to `eval/` or `docs/ASSUMPTIONS.md`.

1. **Slide 1 — Title & Scope:** Vinyas: AI-assisted quality inspection & predictive maintenance for discrete manufacturing (PCB SMT, CNC spindle, MIG weld). Hosted on Google Cloud Run (`asia-south1`). Explicit note: simulated inputs (organiser-approved), real DSP & Google AI decisions.
2. **Slide 2 — The Shop-Floor Problem:** Unplanned spindle failures, fine-pitch PCB bridges, and weld porosity create rework and scrap; operators wear PPE gloves and often prefer Hindi or Marathi over English SOP binders. Economic baseline assumptions documented in `docs/ASSUMPTIONS.md` (unvalidated; customer discovery pending per `docs/CUSTOMER_EVIDENCE.md`).
3. **Slide 3 — Target Users:** Shop-floor Operator (giant PASS/HOLD/STOP verdict, EN/हिन्दी/मराठी voice co-pilot, SOP-guarded steps) and Quality / Maintenance Engineer (Hilbert envelope spectrum, model provenance, attempts trace, human disposition gate).
4. **Slide 4 — Blind Demo Flow:** Draw random part (hidden ground truth) → Inspect (T1-A DSP + hedged T1-B visual gate → T2 Gemini + SOP Guard + T3 Overlay) → Reveal ground truth & session tally → Human disposition (`HOLD/REWORK/SCRAP`) → Multilingual work-order extraction.
5. **Slide 5 — Architecture:** Exact 5-tier pipeline matching README Mermaid diagram (Mock Rig v2 → T1-A NumPy/SciPy DSP → T1-B hedged visual gate `gemini-3.5-flash-lite` → `gemma-4-26b-a4b-it` → `gemini-3.1-flash-lite` → `gemini-embedding-2` 18-SOP retrieval → Hedged T2 `gemini-3.1-flash-lite` / `gemini-3.8-flash` + SOP guard + deterministic economics → T3 deterministic model-bbox overlay → T4 `gemini-3.8-live` WebSocket co-pilot).
6. **Slide 6 — Why Each Google Model:** Non-overlapping roles, each chosen by a measured benchmark with the decision rule fixed before the run: visual gate from `eval/visual_gate_benchmark.md` (`gemini-3.5-flash-lite` caught 14/14 visible defects with 0/32 false alarms; `gemma-4-26b-a4b-it` is the hedged backup and the on-prem edge-client model); Tier-2 from `eval/model_selection.md` (`gemini-3.1-flash-lite` primary, `gemini-3.5-flash-lite` runner-up; `gemini-4-hydrogen` scored `0/8` in run 1 and `gemini-3.8-flash` had no quota). Nano Banana image models hit `429` quota, so they are omitted from runtime.
7. **Slide 7 — Measured Evaluation Results:** Copy headline confusion matrix, true-defect recall, false-escalation rates, per-tier p50/p95 latencies, and SOP-guard unverified count verbatim from `eval/RESULTS.md` (with its mandatory simulated-input header).
8. **Slide 8 — Measured Token Economics & Assumption-Based Impact:** Measured gated vs cloud-only tokens from `eval/RESULTS.md` and `POST /api/line-run`, computed by `compute_gate_token_accounting` (escalations charged at the mean measured Tier-2 cost, so outages never count as savings; the effect depends on the plant defect rate and visual-gate availability) + assumption-based INR avoidable-loss model from `docs/ASSUMPTIONS.md`.
9. **Slide 9 — Competitive Landscape:** Neutral comparison against Infinite Uptime, Altizon, Tractian, Augury, Nanoprecise, LandingLens, Google Cloud Visual Inspection AI, and Siemens Senseye; Vinyas's built differentiators (closed detection→vernacular SOP→disposition→WO loop, measured edge-gate token accounting, multi-modality).
10. **Slide 10 — Limitations, Next Steps & Ask:** Honest limitations (simulated inputs, SQLite demo store, API 503 sensitivity on free tier, no hardware pilot yet); next steps (plant validation in Chakan/Bhosari, paid Vertex AI quota, managed PostgreSQL/AlloyDB deployment).
